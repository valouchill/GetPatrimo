Ajouter express-rate-limit sur tous les endpoints d'authentification (/api/auth/*, /api/login, /api/register) avec un max de 5 requêtes par minute pour le login et 20 par minute pour les API classiques. Installer le package et configurer le middleware dans server.js et dans les API Routes Next.js.
Hasher les tokens magicSignInToken et magicLinkToken avec bcrypt avant de les stocker dans les modèles User et Application. Modifier les méthodes de vérification pour comparer avec bcrypt.compare(). Écrire un script de migration pour hasher les tokens existants en base.
Ajouter express.json({ limit: '1mb' }) et express.urlencoded({ limit: '1mb', extended: true }) dans server.js pour limiter la taille des requêtes et empêcher les attaques DoS par payload.
Installer et configurer helmet dans server.js pour ajouter les headers de sécurité : HSTS, X-Frame-Options DENY, Content-Security-Policy strict, X-Content-Type-Options nosniff, Referrer-Policy strict-origin-when-cross-origin.
Installer express-mongo-sanitize et l'appliquer comme middleware global dans server.js pour nettoyer toutes les entrées utilisateur et empêcher l'injection NoSQL ($ et . dans les clés).
Améliorer la validation des uploads de fichiers : installer file-type pour vérifier les magic bytes du fichier uploadé et pas seulement le MIME type déclaré. Rejeter les fichiers dont le magic byte ne correspond pas au type déclaré. Appliquer dans toutes les routes d'upload.
Remplacer les credentials hardcodées dans docker-compose.yml (admin:password123 et similaires) par des références à des variables d'environnement (${MONGO_USER}, ${MONGO_PASSWORD}). Créer un fichier .env.example avec les variables nécessaires.
Ajouter une politique de mot de passe dans le modèle User et les endpoints de register : minimum 8 caractères, au moins 1 majuscule, au moins 1 chiffre. Ajouter une validation pre-save dans Mongoose et une validation côté API avec un message d'erreur clair.
